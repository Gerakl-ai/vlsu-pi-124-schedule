# Безопасность

## Сообщить об уязвимости

Не публикуйте работающий эксплойт, чужие заметки, резервные копии, токены или персональные данные в открытом issue. Используйте приватное сообщение владельцу репозитория через GitHub либо GitHub Private Vulnerability Reporting, если этот канал включён в настройках репозитория. Опишите затронутый адрес/версию, шаги воспроизведения и влияние без данных реальных пользователей.

Публичный issue подходит для обычного бага интерфейса или неверного расписания без чувствительных данных; порядок приведён в [CONTRIBUTING.md](CONTRIBUTING.md).

## Границы проекта

- Заметки, фото и события хранятся локально в браузере пользователя; origin и профиль браузера изолируют эти данные.
- Публикация нового адреса не переносит хранилище со старого. Не удаляйте старую PWA до проверенного экспорта/импорта.
- GitHub Pages раздаёт статические файлы расписания из ветки `data`. Публичная ветка и логи сборки не должны содержать личные записи или секреты.
- Service worker и механизмы обновления app shell требуют проверки на установленных iOS/Android устройствах перед массовым выпуском.

Формальные сроки реакции и официальный ответственный пока не утверждены. До университетского пилота это необходимо согласовать отдельно.
