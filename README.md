# Лад ВлГУ

Открытая mobile-first PWA для расписания групп ВлГУ и личных умных заметок.

## Текущий продуктовый этап

- На первом запуске студент выбирает институт и группу из публичного каталога ВлГУ.
- Выбранная группа хранится локально; расписания разных групп имеют независимые кэши.
- Старые установки ПИ-124 автоматически мигрируют на новую схему без удаления прежнего кэша.
- Worker сохраняет только валидные ответы и в фоне обновляет снимки реально используемых групп.
- Расписание и тип недели приходят единым `snapshot:v2`, поэтому клиент не смешивает данные разных обновлений.
- Повреждённый локальный кэш не блокирует запуск, а service worker обновляет HTML и hashed assets как одну версию.
- ПИ-124 остаётся совместимым профилем для существующих пользователей, но больше не зашита в API-адаптер.
- Избранные группы и прямые ссылки ускоряют переключение; предметные заметки изолированы по выбранной группе.

Расписание читается из статических снимков, собираемых GitHub Actions: [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md).

План превращения персональной версии в открытый мультигрупповой продукт: [docs/VLSU-PRODUCT-ROADMAP.md](docs/VLSU-PRODUCT-ROADMAP.md).

## Возможности

- живое расписание ВлГУ с cache-first запуском и offline reload;
- автоматическое восстановление установленной PWA при несовместимом или устаревшем app shell без удаления записей;
- экраны «Сегодня», «Неделя», «Записи» и «Настройки»;
- восемь авторских тем и собственная тема с настройкой фона, текста, акцентов и поверхностей;
- корректное представление одновременных занятий разных подгрупп без склеивания предметов и аудиторий;
- rich-text редактор заметок с заголовками, чек-листами, цветом текста, выделением, цитатами и списками;
- автосохранение черновиков, голосовой ввод и прикрепление масштабируемых фотографий;
- локальная классификация по контексту, пользовательские папки и автоматическая привязка домашних заданий к предметам;
- адаптивная компоновка для портретного и горизонтального положения телефона;
- локальные напоминания, PWA manifest, service worker и резервная копия записей.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Приложение откроется на `http://127.0.0.1:5173/`.

## Проверки

```bash
pnpm typecheck
pnpm test
pnpm build
pnpm cloudflare:check
```

Команда `pnpm check` запускает весь набор. Те же проверки выполняются в GitHub Actions для `main` и pull request.

## GitHub Pages

Основной вариант деплоя. Приложение статическое, а расписание приходит снимками
из ветки `data` — см. [docs/DATA-PIPELINE.md](docs/DATA-PIPELINE.md). Публикацию
выполняет workflow `.github/workflows/pages.yml`.

## Cloudflare Workers

Прежний вариант деплоя. Остаётся рабочим: приложение перебирает источники по
порядку, поэтому установленная версия на Workers продолжает получать данные.

```bash
pnpm build
pnpm deploy
```

`wrangler.jsonc` публикует `dist`, направляет `/vlsu-api/*` и `/app-api/*` через `src/worker.ts`, а также подключает binding `CF_VERSION_METADATA`. Версия Wrangler зафиксирована в `package.json`, поэтому локальный и Git-деплой используют один инструмент.

Для Cloudflare Workers Builds с GitHub:

```text
Production branch: main
Build command: pnpm build
Deploy command: pnpm exec wrangler deploy
```

Каждый push в `main` запускает сборку. Активную ревизию можно проверить запросом `GET /app-api/health`: endpoint возвращает release channel, Worker version ID и время создания версии.

## Cloudflare Pages

Pages остаётся совместимым вариантом для расписания:

```text
Build command: pnpm build
Build output directory: dist
```

`functions/vlsu-api/[[path]].ts` проксирует API ВлГУ для прежних развёртываний. Разбор записей выполняется на устройстве и внешних сервисов не требует.

## Уведомления

Локальное напоминание работает, пока браузер может выполнить запланированный код. Для гарантированной доставки при полностью закрытом приложении нужен Web Push: установленная на экран «Домой» PWA, push subscription и серверный отправитель. Service worker уже умеет принимать push-события, но серверная регистрация подписок в эту локальную версию не входит.

## Данные и приватность

Расписание кэшируется локально. Записи, пользовательские папки, черновики и вложенные изображения хранятся в IndexedDB текущего устройства. Классификация записей выполняется целиком в браузере: внешних сервисов и облачной обработки текста нет.
